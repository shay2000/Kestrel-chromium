# Kestrel desktop and advanced workflow test log — 5 November 2026

This is a test-only comparison of the Chromium build against the original Kestrel WebKit 1.0.0 release. No application fixes are included.

The subsequent [implementation and retest record](docs/DESKTOP_PARITY_FIXES_2026-11-06.md) tracks fixes and corrections to test setup. The findings below describe the original audit; they are not the current acceptance status.

## Scope and runner

- Chromium source under test: `757a17f779ea6dfe01527500c1189e4cebaedc09` (published 1.0.2 preview).
- Comparison baseline: the latest available shipped `Kestrel-Browser` v1.0.0 Mac release, run on the same hosted Mac. The upstream repository's latest commit only refreshes showcase screenshots; its checked-in Xcode project cannot build the current-source WebKit app.
- The current execution workspace is Linux and cannot operate AppKit or macOS window controls. The audit is being run on the repository's hosted macOS 26 workflow.
- Existing CI already covers first-click focus, page/header geometry, drag/minimise/restore, window ownership, lifecycle cancellation, extension actions and a basic same-page visual comparison. This pass adds repeated desktop workflows, native menu/submenu inspection and a full native unit run.

## Findings

Chromium's “No saved chats” menu is a reproducible product-level difference: the seeded archive retained 12 records, while the menu showed no chats and could not open Recent Chats. Chromium's split keyboard command navigated back. Replaying “Move Tab to Left Split” from the Tabs menu registered split state, but the left page stayed blank and the layout exposed only one address field, unlike WebKit's two visible pages and address fields. After a Tabs-menu interaction, one keyboard focus-and-type sequence failed to replace the address; pointer focus succeeded and later keyboard navigation worked. Treat this as an intermittent focus/input issue. WebKit completed all advanced workflows, including attachment persistence, New Chat reset, and Settings-window close. Its v1.0.0 composer labels its mode control “Browse”; current-source comparison remains blocked by the stale Xcode project. The native FIDO QR remains absent on the hosted Mac; the captured screen is a Bluetooth-enable prompt, while synthetic WebAuthn and cancellation paths pass. A prior WebKit Cmd-W attempt that left no accessible app window remains unverified.

No product fixes are included. A passing harness step will not be treated as proof for flows it does not exercise, including real provider-backed Agent actions, profile filling, page-image delivery, Codex helper sign-in, or physical phone passkey ceremonies.
