# Kestrel Chromium 1.0.0 — Preview 2

Fixes the extra full Chromium window that appeared after installing an extension. Installing Google Translate now leaves the extension in Kestrel's own profile and UI. Extension welcome pages, including Dark Reader's help page, open as Kestrel tabs. Valid extension options pages keep their extension origin.

The previous preview's install/restart tests verified extension installation and effects but missed the additional native browser window. The revised Mac acceptance records every native window and page target, rejects escaped Chromium toolbar windows, requires Dark Reader's welcome page, and invokes a disposable extension's actual `chrome.runtime.openOptionsPage()` API. Both real Store installations, Dark Reader's live styling and clean restart are checked again. Browser lifetime, native permission confirmation, Chromium's renderer sandbox and Kestrel's shared browser UI are retained.

Download **Kestrel-Chromium-1.0.0-arm64.dmg** and its `.sha256` sidecar. This is **Apple silicon only**, targets macOS 14+, and was tested on macOS 26.6.2 ARM64. The app is **ad-hoc signed and not notarised**; macOS may block its first launch. No Intel binary, Developer ID/Gatekeeper acceptance or signed automatic-update appcast is supplied. Replace the older preview app with this build; both previews use application version 1.0.0, while their release tags and checksums differ.

This promotes the exact clean DMG from [successful Mac run 41214983097](https://github.com/shay2000/Kestrel-chromium/actions/runs/41214983097), source/tag target `51fd1003aa7a3be3c3e834487e577b9c6a5b34db`. The CI extension fixture is removed before packaging. The publication job verifies the original artifact digest and DMG checksum, mounts and signature-checks the app, then downloads the uploaded assets and compares their hashes before publishing.

Compatibility remains bounded. Initial welcome/options GET navigation is routed into Kestrel; this is not complete `chrome.tabs`/`chrome.windows` virtualisation, and provisional native tab IDs are not preserved. Workflows using those IDs, delayed blank-tab updates, POST-created tabs, other profiles and native extension action popups still need separate acceptance. Request bodies and another profile's state are not copied.

Physical phone/QR passkey sign-in remains unverified. The runner reached Chromium's Bluetooth setup; a separate virtual FIDO2 test passed. Apple's iCloud Passwords extension still depends on Apple's accepted signed browser identity, which the current ad-hoc Kestrel build does not have. Installing an extension does not establish password-manager or passkey compatibility. No credential-store bridge, paid passkey service, personal account or fabricated entitlement is added.

The original WebKit release and update feed are unchanged. This preview does not merge the Chromium review branch into `main`.
