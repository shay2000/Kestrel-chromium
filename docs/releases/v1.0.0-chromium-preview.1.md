# Kestrel Chromium 1.0.0 — Preview 1

An Apple silicon preview of Kestrel's Chromium engine, with the native browser UI retained from the WebKit version.

- Fixes browser shutdown/quit races, popup ownership, cancelled tab closure and stale page overlays. Keeps the Chromium renderer sandbox enabled.
- Native Chrome Web Store installation and clean restart passed for Google Translate and Dark Reader; Dark Reader modified a page again after restart. Compatibility with the entire Store catalogue is not established.
- The packaged app passed native lifecycle/crypto regressions and visible browser acceptance on macOS 26.6.2 ARM64 / Xcode 26.6. The original WebKit 1.0.0 app was compared on the same runner/page. This comparison does not establish parity for every feature.

Download **Kestrel-Chromium-1.0.0-arm64.dmg** and its `.sha256` sidecar. This build is **Apple silicon only**, targets macOS 14+, and was tested on macOS 26.6.2. It is **ad-hoc signed and not notarised**; macOS may block the first launch. An Intel build and Developer ID/Gatekeeper acceptance are not supplied.

The release promotes the exact clean DMG from [passing Mac run 41208164060](https://github.com/shay2000/Kestrel-chromium/actions/runs/41208164060), source `a3e63faab8e002bfb2c1f618f4f1c0a9390f7ed0`. The CI extension fixture was removed and the app re-signed before packaging. No account credentials or personal browser profile are included. Published asset bytes are downloaded again and checked against the original SHA-256 before publication completes.

**Authentication limits:** Chromium's phone/QR route needs working Bluetooth, network access and a nearby compatible phone with the site's passkey. The hosted runner reached Bluetooth setup but did not complete a physical QR ceremony; working phone sign-in is not a release claim. A separate synthetic FIDO2 round trip passed. Apple's official iCloud Passwords extension is blocked for the current Kestrel identity by its macOS native-helper browser restrictions; installing it does not grant Apple Passwords or passkey access. [Apple's explanation](https://github.com/apple/password-manager-resources#how-apple-uses-web-browser-extension-distribution-information). Extension-provider passkey ceremonies remain unverified.

Other remaining acceptance includes the Settings extension importer, extension action popups, provider/native-host flows and the optional Codex executable, which is not bundled here. The Chromium profile is separate from WebKit cookies/history. This preview does not change the original WebKit release or its update feed. Download future Chromium previews from this repository's Releases page; this release has no signed automatic-update appcast.
